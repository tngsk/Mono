# Mono v2.0 ロードマップ: 学習コンテンツ向けデザインシステムと閲覧性の向上

Mono v1.0のリリースを経て、v2.0では「学習コンテンツとしての魅力と実用性の向上」をメインテーマに据えます。特に、教育現場や自己学習における多様な閲覧コンテキスト（プロジェクター投影、スマートフォン、PC）に柔軟に適応できるアーキテクチャの構築を目指します。

本ドキュメントでは、v2.0に向けた具体的な設計指針と提案をまとめます。

## 1. デザイントークンとデザインシステムの本格導入

現在、`themes.toml`で色（Color）を管理し、`base.css`で余白（Spacing）などの変数を定義していますが、これを拡張し、一貫したデザインシステムを構築します。

### 提案内容
- **トークンの拡充**:
  色だけでなく、タイポグラフィ（フォントファミリー、行間、ウェイト）、余白（Spacing Scale）、角丸（Border Radius）、シャドウ（Elevation）などを `themes.toml` （または分割した設定ファイル）で包括的に管理できるようにします。
- **意味的（Semantic）トークンの導入**:
  学習コンテンツ特有のコンテキストに合わせた変数（例: `--color-hint` (ヒント用), `--color-quiz-success` (正解時), `--color-alert` (注意喚起)）を定義し、UIの意図を明確にします。
- **コンポーネントの標準化**:
  すべてのカスタムWeb Components (`mono-*`) が、ハードコードされた値ではなく、これらのグローバルなCSS変数（デザイントークン）を厳格に参照するようリファクタリングします。これにより、テーマ切り替え時の視覚的破綻を防ぎます。

## 2. スクリーン投影（プロジェクター）への最適化

教室や会議室でのプロジェクター投影では、一般的なPC画面とは異なる視認性が求められます。

### 提案内容
- **プレゼンテーションモード（Presentation Mode）の導入**:
  現在の `mono-theme` コンポーネントのフォントサイズ変更機能を拡張し、一括で「投影用UI」に切り替える仕組み（例: `data-presentation="true"` 属性の付与）を導入します。
- **ダイナミックなコントラストとサイズ調整**:
  投影モード時は、ベースフォントサイズを大幅に引き上げるとともに、プロジェクターの低い色再現性を考慮して、テキストや境界線のコントラスト比を自動的に高める（ハイコントラストテーマの自動適用など）仕組みを設けます。
- **スライド型レイアウトのサポート強化**:
  `mono-section` や `mono-hero` を用いたフルブリード（全幅）コンポーネントを活用し、CSSの `scroll-snap` を用いたスライド風のページネーション（縦または横へのスナップスクロール）を標準でサポートします。

## 3. 多様なデバイス（PC・スマートフォン）での閲覧性向上

学習者が手元のスマートフォンやタブレットで学習する際のUXを向上させます。

### 提案内容
- **Fluid Typography と CSS Grid の改善**:
  現在 `base.css` で定義されている `grid-template-columns: minmax(1rem, 1fr) minmax(auto, 900px) minmax(1rem, 1fr)` の中央カラム幅の制御を見直し、`clamp()` 関数を用いた流体タイポグラフィや余白の動的計算を導入します。これにより、モバイル端末での水平オーバーフローを根本的に防ぎ、常に最適な1行あたりの文字数（45〜75文字）を維持します。
- **タッチターゲットの最適化**:
  スマートフォンでの操作性を考慮し、すべてのインタラクティブなコンポーネント（ボタン、入力フィールド、`mono-flipcard`、`mono-dice` など）のタップ領域をアクセシビリティ基準（最低44x44px）に準拠させます。

## 4. コンテキストに応じた情報提示の柔軟性（Context-Aware Presentation）

紙の教科書や従来の固定的なPDFにはない、Web技術ならではの「状況に応じた情報の出し分け」を実現します。

### 提案内容
- **アダプティブ・コンポーネント（Adaptive Components）の開発**:
  画面幅や現在の表示モード（個人学習モード vs プレゼンモード）に応じて、表示内容を切り替えるコンポーネント（例: `mono-adaptive`）を新設します。
  *例: スマホでは「概要図」を表示し、PCや投影時には「詳細なデータテーブル」を表示する。*
- **フォーカスモード（Focus Mode）とプログレッシブ開示**:
  学習者が現在読んでいる段落やセクション以外を暗くする「フォーカスモード」や、ヒントや詳細な解説を最初は隠しておき、クリック（タップ）で展開する「プログレッシブ・ディスクロージャー（例: `mono-details` コンポーネント）」を標準化します。
- **役割に応じた表示（Role-Based Visibility）**:
  `mono-account` やセッション機能と連携し、「教員用」の解説ブロックと「生徒用」のブロックを分け、認証状態に応じて動的にDOMの表示/非表示を切り替える機能を検討します。
